3. API

Use the existing AfuChat namespace:

/v1/chat/*

Do NOT create:

/v1/profile/*
/v1/users/*
/v1/contact/*

The operation belongs to AfuChat.

Prefer an existing profile API if one already exists.

Before creating a new endpoint, inspect:

artifacts/mobile/lib/afuchatApi.ts

and the existing "afuchat-api" Worker routes.

If no suitable operation exists, add one specifically for retrieving a public/other-user profile.

For example, use the existing "/v1/chat/*" architecture and choose a route consistent with the current API conventions.

Do not create duplicate profile endpoints.

---

4. SECURITY

The profile endpoint must be server-authoritative.

The requested profile ID may identify the profile being viewed.

But authorization must still be based on the authenticated AfuAuth bearer token.

Do not trust a client-supplied ID as proof of ownership.

Apply the existing profile privacy rules.

In particular, do not accidentally expose fields that should remain private.

Never return sensitive profile fields merely because they exist in "accounts.profiles".

---
