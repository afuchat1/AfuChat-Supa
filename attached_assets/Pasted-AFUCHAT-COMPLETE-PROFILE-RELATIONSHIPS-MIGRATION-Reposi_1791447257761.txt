API DESIGN RULES

All Profile Relationship API operations belong under:

/v1/chat/*

Examples of acceptable operations:

/v1/chat/follows/summary
/v1/chat/follows/status
/v1/chat/follows/list
/v1/chat/follows/ids
/v1/chat/follows

For blocks/restrictions, follow the same namespace:

/v1/chat/*

Use clear resource-specific routes.

Do not create:

/v1/relationships/*
/v1/followers/*
/v1/following/*
/v1/blocks/*

The product namespace is AfuChat.

---

AUTHENTICATION

Every relationship API operation must use the authenticated AfuChat session.

The server must derive:

currentUserId

from the verified bearer token.

Never trust:

follower_id
blocker_id
owner_id

from the client as the authoritative identity.

Client IDs may only be used as optional consistency assertions.

---

PRIVACY AND SECURITY

Relationship data can expose sensitive social-graph information.

Therefore:

private profiles
hidden follower lists
hidden following lists
blocked relationships
restricted relationships

must be enforced server-side.

Do not return information the current user is not allowed to see.

Do not allow enumeration of private relationship data through arbitrary IDs.
