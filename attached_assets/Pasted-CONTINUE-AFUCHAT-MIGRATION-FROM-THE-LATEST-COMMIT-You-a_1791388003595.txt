8. IMPORTANT: NEVER TRUST "expected_user_id"

The current API client sometimes sends:

This may be retained as an optional consistency assertion.

But it must NEVER establish identity.

The server must do:

Bearer token
    ↓
AfuAuth verification
    ↓
authenticated user ID
    ↓
authorization

NOT:

    ↓
assume this is the caller

If "expected_user_id" is supplied, the server may verify that it matches the authenticated identity.

If it does not match:

But the token-derived identity remains authoritative.

Apply the same rule to:

profile_id

The client must not be able to impersonate another user simply by changing an ID.
