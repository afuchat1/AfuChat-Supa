# AfuCloud – Master Development Specification

## Project Overview

Build **AfuCloud** as a modern cloud platform focused on storing, processing, managing, and delivering digital assets through a professional developer-first API.

The first production service is **Images**, but the architecture must be designed to support additional asset types in the future without requiring a redesign.

The platform must be fast, scalable, secure, modular, and production-ready.

---

# Core Principles

* AfuCloud must present itself as its own cloud platform.
* Users and developers must only interact with AfuCloud.
* Infrastructure providers are implementation details and must never be exposed.
* Build the project with clean architecture and long-term scalability in mind.
* Every feature must be designed for production use.

---

# Public Domains

The platform must only expose AfuCloud domains.

Examples

* cloud.afuchat.com
* api.afuchat.com
* img.afuchat.com

No client should ever see infrastructure provider URLs.

# Architecture

Build the system using a modular architecture.

Modules include:

* Authentication
* Users
* Projects
* Storage
* Images
* Search
* Analytics
* API
* Developer Console
* Administration

Each module must be independent and maintainable.

---

# Authentication

Implement authentication through the AfuCloud API.

Support:

* Email and password
* JWT access tokens
* Refresh tokens
* Session management
* Email verification
* Password reset
* Multiple active sessions
* Logout from all devices

Never expose direct Supabase authentication endpoints.

---

# Projects

Users must be able to create multiple projects.

Each project contains:

* Storage
* Images
* API Keys
* Personal Access Tokens
* Analytics
* Webhooks
* Settings
* Permissions

---

# Personal Access Tokens

Allow users to create Personal Access Tokens.

Each token must support:

* Name
* Description
* Expiration
* Status
* Last used
* Created date
* Revocation
* Regeneration
* Fine-grained permissions

The secret token must only be displayed once during creation.

---

# API Keys

Support separate API keys for:

* Development
* Production
* Testing

Keys must support permission scopes.

---

# API Gateway

Every request must go through:

https://api.afuchat.com

Version the API.

Example:

/v1/

Provide:

* Authentication
* Authorization
* Validation
* Rate limiting
* Logging
* Error handling
* Monitoring

---

# Storage Layer

Implement a storage abstraction layer.

The application must never communicate directly with the storage provider.

Required methods include:

* upload
* download
* delete
* copy
* move
* list
* exists
* generatePublicURL
* generateSignedURL
* generateTemporaryURL

The implementation must allow changing the storage provider in the future without affecting the rest of the application.

---

# Database Layer

Implement a repository layer.

All database operations must go through repositories.

Do not scatter database queries throughout the application.
